# Telegram-панель управления OpenCode

Дата: 2026-11-19. Машина: локальный сервер.

## 1. Что и зачем

Один пользователь, владелец машины. С телефона управлять OpenCode, который уже
работает на этой машине: вести несколько задач параллельно в разных проектах,
получать уведомления о завершении, подтверждать опасные действия, останавливать
задачи, менять модель и агента, перезапускать сервис. Бот должен работать и с
сессиями, начатыми на десктопе.

## 2. Границы

Входит: список сессий со статусом, создание сессии в выбранном проекте,
продолжение, отправка текста, выбор модели и агента, остановка, удаление,
подтверждения прав, перезапуск сервиса OpenCode, уведомления, живой прогресс.

Не входит: несколько пользователей и роли, вложения файлов и голос, PTY и
терминал, git-операции, перезагрузка хоста, авто-подтверждения, публичный
вебхук.

Антицели: молчаливое авто-подтверждение; утечка токенов; одна зависшая задача
блокирует остальные; потеря управления при перезапуске сервера.

## 3. Опора (проверено на машине)

- OpenCode 2.3.0, фоновый сервис `http://127.0.0.1:49374`, HTTP basic auth:
  пользователь `opencode`, пароль из `/home/user/.config/opencode/service.json`.
- Проверенные эндпоинты: `/api/session` (list, create, prompt, interrupt,
  delete, patch, move, switchModel, switchAgent, message), `/api/project`,
  `/api/model`, `/api/agent`, `/api/permission/request` и
  `/api/session/{id}/permission/{requestID}/reply` с решением
  `once | always | reject`, `/api/event` (SSE), `/api/info`,
  `/api/session/active`.
- Доставка сообщения: `delivery = queue | steer`.
- Занятость сессии: `time.busy > time.idle` плюс `outcome`.
- Telegram: long polling, лимит 4096 символов, правки сообщений с троттлингом.
- Python 3.12, uv, systemd user с linger (уже включен).

## 4. Архитектура

Один долгоживущий процесс `opencode-telegram-bot`: Python 3.12, aiogram 3,
httpx, aiosqlite, pydantic 2, pydantic-settings.

Модули: `config`, `opencode/{models,client,events,service}`, `store`,
`formatting`, `keyboards`, `progress`, `permissions`, `notifications`,
`ui/*`, `handlers/*`, `app`, `main`.

Поток: обновление Telegram -> handler -> API OpenCode. События API -> SSE ->
диспетчер -> сообщения и правки в затронутые чаты. Финальный ответ читается из
`/api/session/{id}/message` (последняя текстовая часть ассистента), а не
склеивается из дельт.

SQLite: `chats` (активная сессия, notify_all), `subscriptions`,
`progress` (сообщение прогресса на сессию и чат), `permission_messages`
(запрос, чат, сообщение, время отправки, напоминали ли), `meta`.

## 5. Экраны

Главное меню: Сессии, Новая задача, Модели, Сервис.

Сессии: 8 на страницу, иконка статуса, проект, модель, поиск по названию.
Карточка: продолжить, модель, агент, стоп, удалить, уведомления, обновить.

Новая задача: проект из `/api/project` по активности плюс ручной ввод пути ->
модель (по умолчанию или текущая) -> текст -> создание.

Текст в чате уходит в активную сессию. Если она занята: кнопки "В очередь",
"Вклиниться", "Отмена".

Модели: провайдер -> модель, текущая помечена, есть выбор "по умолчанию".

Сервис: статус (URL, pid, версия, число занятых сессий), перезапуск с
подтверждением.

## 6. Подтверждения

Строгий профиль для сессий, созданных ботом: `allow *`, затем `ask` для
`shell`, `edit`, `webfetch`, `external_directory`, `read` для `*.env` и
`*.env.*`. Десктопные сессии сохраняют свои права.

Правила сессии проверяются на живом сервере. Если правила агента перекрывают
правила сессии, в глобальный конфиг добавляется агент `telegram` с этим
профилем, и бот-сессии создаются с ним. Конфиг перечитывается без перезапуска.

Запросы прав приходят в Telegram от любой сессии, включая начатые на десктопе,
независимо от подписки: иначе такая задача зависнет без возможности ответить.
Сообщение: действие, ресурсы, источник, кнопки "Разрешить", "Всегда",
"Отклонить". "Всегда" сохраняет правило глобально, об этом пометка в тексте.
Если ответили на десктопе, сообщение в боте меняется на "уже решено".
Таймаута нет, напоминание через 5 минут, пока не решено.

## 7. Уведомления

Подписка при создании и продолжении сессии. По `execution.succeeded`,
`execution.failed` и `session.idle`: "Сессия «...» завершилась", итог,
длительность, стоимость, первые 300 символов ответа, кнопка "Открыть". Есть
общий переключатель "уведомлять обо всех сессиях".

Дочерние сессии субагентов в списке скрыты; их завершения сворачиваются в
родительскую сессию одним сообщением, без отдельного пинга.

## 8. Живой прогресс

Одно редактируемое сообщение на активную сессию, не чаще раза в 2 секунды:
текущий инструмент, последние ~600 символов текста, затраченное время. При
завершении сообщение превращается в итог, финальный ответ приходит отдельным
сообщением, длинный текст режется по абзацам с соблюдением лимита 4096.

## 9. Устойчивость

SSE переподключается с backoff (1, 2, 5, 10, 30 с). После реконнекта бот
перечитывает активные сессии и ожидающие подтверждения: события не
единственный источник истины. 404 -> обновить список. Ошибка API -> сообщение
с кнопкой "Повторить". Один экземпляр бота через flock.

Своего systemd-юнита для OpenCode нет: если сервер лежит, бот поднимает его
через `opencode service start`. Перезапуск затрагивает только сервис OpenCode,
с предупреждением о занятых сессиях. После перезапуска опрос `/api/info` до
30 секунд; при неудаче подсказка про
`~/.local/share/opencode/log/opencode.log`.

## 10. Безопасность

Allowlist Telegram user id; остальные игнорируются и логируются. Токен и
пароль только в env-файле с правами 600, в логи не попадают (фильтр
редактирования). Только исходящие соединения. Удаление и перезапуск требуют
подтверждения. Никаких авто-подтверждений в первой версии.

## 11. Деплой

Код: `/opt/opencode-telegram-bot/`, отдельный git
репозиторий. venv через uv. systemd user unit
`opencode-telegram-bot.service`, `Restart=always`,
`EnvironmentFile=/home/user/.config/opencode/telegram-bot.env`, логи через
`journalctl --user -u opencode-telegram-bot`.

## 12. Проверка

Юнит-тесты: форматирование и нарезка, разбор событий, роутинг, хранилище,
API-клиент на respx. Read-only smoke к живому серверу. E2E в Telegram: создать
сессию в `/tmp/opencode/bot-e2e`, получить ответ, вызвать и подтвердить запрос
прав, запустить долгую команду, переключиться на вторую сессию, получить
уведомление, остановить, удалить, перезапустить сервис и проверить
восстановление. Убедиться, что токен не попал в журнал.

## 13. Решения автора

- Нет таймаута подтверждений; напоминание через 5 минут.
- Уведомления по подписке плюс общий переключатель.
- Прогресс в одном редактируемом сообщении, финальный ответ отдельно.
- Перезапускается только сервис OpenCode, не хост.
- Код в подпапке текущего проекта, отдельный git репозиторий.
- Двухуровневое меню моделей.
- Строгий профиль прав только для бот-сессий.

## 14. Открыто к запуску

Токен от BotFather и Telegram user id нужны на этапе запуска, в переписку не
передаются.
